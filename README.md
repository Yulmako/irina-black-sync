# Irina Black CRM — независимая веб-панель

Полностью самостоятельный инструмент: работает без Claude и без моего
участия. Всё, что нужно, — два бесплатных аккаунта (GitHub и Supabase),
которые сейчас заводятся на вашу почту, а дальше их можно передать
владелице салона (это просто смена логина/пароля в этих сервисах,
данные и код никуда переносить не нужно).

**Я не могу создавать аккаунты сама** (это ограничение моей же
безопасности) — но каждый шаг ниже занимает пару минут и не требует
навыков программирования.

Как это устроено:
- **GitHub Actions** — раз в час сам заходит в ваш кабинет zapis.kz
  (по уже готовой сессии) и обновляет записи в Supabase. Работает в
  облаке GitHub, компьютер для этого не нужен.
- **Supabase** — бесплатная база данных. Хранит и записи из zapis.kz,
  и всё, что салон вносит вручную (мастера, прайс расходников,
  закрытие дня, инвентаризация, P&L) — отдаёт всё это панели только
  если передан правильный общий пароль.
- **GitHub Pages** — бесплатный хостинг самой веб-страницы (`docs/index.html`).

Вкладки панели: **Записи** и **Клиенты** (из zapis.kz, автоматически),
**Мастера**, **Расходники Прайс**, **Инвентаризация**, **Аналитика**,
**Закрытие дня** и **P&L** (эти шесть салон ведёт сам, прямо в панели —
всё сохраняется в Supabase).

## Шаг 1. Создайте аккаунт на GitHub

[github.com](https://github.com) → Sign up. Бесплатно.

## Шаг 2. Создайте репозиторий и загрузите файлы проекта

1. **New repository** → назовите, например, `irina-black-crm`.
   Можно **Public** — никаких паролей и личных данных в самом коде нет,
   всё чувствительное хранится отдельно как секреты или в базе данных.
2. **Add file → Upload files** → перетащите туда всю папку
   `salon-crm-web` целиком, сохранив структуру (`.github/workflows/`,
   `scripts/`, `docs/`, `supabase/`). Подтвердите коммит.

## Шаг 3. Включите GitHub Pages

1. В репозитории: **Settings → Pages**.
2. **Source**: Deploy from a branch.
3. **Branch**: `main`, папка **`/docs`**. Сохраните.
4. Через минуту-другую там же появится адрес вида
   `https://ваш-логин.github.io/irina-black-crm/` — это и есть ссылка
   на панель, которую можно давать сотрудникам.

## Шаг 4. Создайте проект в Supabase

1. [supabase.com](https://supabase.com) → Sign up (бесплатно) → **New project**.
2. Задайте пароль базы данных (сохраните его отдельно — он понадобится
   разве что для прямого доступа к базе, панели он не нужен) и дождитесь
   создания проекта (1–2 минуты).
3. Слева откройте **SQL Editor → New query**, вставьте туда содержимое
   файла `supabase/schema.sql` из проекта и нажмите **Run**.
   Это создаст таблицы (включая хранилище для мастеров, прайса,
   закрытия дня, инвентаризации и P&L) и защитит их: без правильного
   пароля панель не получит ни строчки данных.

   Уже есть работающий проект Supabase с более ранней версией схемы?
   Просто вставьте новый `supabase/schema.sql` в SQL Editor и нажмите
   **Run** ещё раз — каждая команда там безопасно повторяется
   (`create if not exists` / `create or replace`), новая таблица
   `app_kv` добавится, а записи и пароль не пострадают.

## Шаг 5. Задайте свой общий пароль для сотрудников

В том же **SQL Editor** выполните (замените `ваш-пароль` на настоящий):

```sql
update app_access set shared_password = 'ваш-пароль' where id = 1;
```

Этот пароль вводят сотрудники при первом заходе на страницу панели —
дальше браузер его запоминает. Он открывает все вкладки, кроме P&L —
у неё свой отдельный пароль. Он хранится в базе: выполните один раз
`supabase/passwords.sql` в Supabase (SQL Editor), и оба пароля — общий
и P&L — можно менять прямо на сайте во вкладке «Настройки». До этого
работает запасной пароль из файла панели (`const PNL_PASSWORD` в
`docs/index.html`).

## Шаг 6. Заберите ключи Supabase и впишите их в панель

1. **Project Settings → API**.
2. Скопируйте **Project URL** и ключ **anon public**.
3. В репозитории на GitHub откройте `docs/index.html`, нажмите ✏️
   (Edit), найдите строки:
   ```js
   const SUPABASE_URL = 'https://YOUR-PROJECT.supabase.co';
   const SUPABASE_ANON_KEY = 'YOUR-ANON-PUBLIC-KEY';
   ```
   и вставьте туда свои значения. **Commit changes.**

   `anon public` ключ — это не секрет в обычном смысле: его специально
   можно публиковать на сайте, он не даёт прямого доступа к таблицам
   (см. `supabase/schema.sql` — доступ только через функции с паролем).

4. Там же скопируйте ключ **service_role** (он с пометкой «secret» —
   его публиковать нельзя, он идёт только в секреты GitHub на следующем шаге).

## Шаг 7. Настройте синхронизацию с zapis.kz

**7.1 — скопируйте токен сессии** (замена пароля, вы делаете это сами,
я его не вижу):

1. Откройте [zapis.kz](https://zapis.kz/partner/f/0/main) в браузере,
   войдите в свой кабинет.
2. Откройте инструменты разработчика (**F12**) → вкладка **Network**.
3. Обновите страницу. Найдите запрос к `reservation/list` или
   `masters-list`, кликните на него.
4. **Headers → Request Headers** → найдите строку `Cookie:` и
   скопируйте всё, что идёт после неё.

**7.2 — добавьте секреты в репозиторий:**

**Settings → Secrets and variables → Actions → New repository secret.**
Добавьте три секрета:

| Имя | Значение |
|---|---|
| `ZAPIS_COOKIE` | то, что скопировали в 7.1 |
| `SUPABASE_URL` | Project URL из шага 6 |
| `SUPABASE_SERVICE_KEY` | ключ `service_role` из шага 6 |

**7.3 — запустите первую синхронизацию вручную:**

**Actions → Sync zapis.kz bookings into Supabase → Run workflow.**
Через минуту проверьте — запуск должен завершиться зелёной галочкой.

С этого момента синхронизация идёт сама, каждый час — по расписанию в
`.github/workflows/sync.yml`. Ни ваш компьютер, ни Claude для этого
не нужны.

## Шаг 8. Заполните историю 2026 года (один раз)

Панель умеет показывать записи и весь ручной учёт (мастера, прайс,
закрытие дня, инвентаризация, P&L) только с того момента, как в
Supabase появятся данные. Чтобы не начинать с пустой панели, есть
одноразовый импорт уже сверенной истории с января по август 2026 —
те же цифры, что и в собственных таблицах салона.

**Actions → Seed 2026 history into Supabase → Run workflow.**

Использует те же секреты `SUPABASE_URL`/`SUPABASE_SERVICE_KEY`, что и
синхронизация — новых заводить не нужно. Через минуту-другую откройте
ссылку панели (шаг 3), введите пароль — все вкладки должны показать
данные за 2026 год.

Запускать второй раз безопасно: скрипт не перезаписывает то, что уже
внесено вручную в панели или синхронизировано из zapis.kz после
первого запуска — он только добавляет то, чего ещё нет.

## Если синхронизация остановится

Сессия zapis.kz рано или поздно истечёт — заранее неизвестно, через
сколько (может через несколько недель, может раньше). Когда это
случится, часовой запуск начнёт завершаться с ошибкой, и GitHub
автоматически пришлёт письмо на почту владельца репозитория с темой
вроде «Run failed». Это сигнал повторить шаг 7.1–7.2 (скопировать
новый cookie и обновить секрет `ZAPIS_COOKIE`) — на этом всё
возобновится само.

Ручной учёт (мастера, прайс, закрытие дня, инвентаризация, P&L) от
этого никак не зависит и продолжает сохраняться в Supabase как обычно.

## Когда будете готовы передать доступ салону

Ничего пересобирать не нужно — переносится всё через смену владельца
существующих аккаунтов:

- GitHub: **Settings репозитория → Transfer ownership**, либо просто
  смените email/пароль аккаунта на аккаунт владелицы.
- Supabase: в организации проекта можно добавить второй email как
  Owner, а свой потом убрать (**Organization → Members**).

## На будущее: личные логины сотрудников

Сейчас все вкладки, кроме P&L, открыты по одному общему паролю, а P&L —
по своему отдельному. Supabase умеет полноценную авторизацию по email
(с разными правами: кто-то только смотрит, кто-то редактирует инвентарь
или закрытие дня) — переход на личные логины не потребует менять базу
данных, только добавить экран входа. Дайте знать, когда будете готовы —
допишу.
